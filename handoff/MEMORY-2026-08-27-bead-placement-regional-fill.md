# MEMORY · 2026-08-27 拼豆「亲手拼入」交互 + 区域成块浮现 fill_order

> 本文件是不可变更的里程碑节点（决策过程 + 验收数据）。后续改动请写 STATUS/CHANGELOG。

## 1. 背景（产品拍板）

用户实测 2026-08-26 版作品系统后结论：「数据上已经在拼，但体验上没有『我在拼』的感觉」，
交互链路断裂，拍板三项改动：

1. **全局随机撒点 → 连续区域逐步浮现**：随机 fill_order 让 14% 进度像"预览图打噪点"，
   用户看不出"哪里拼好了一块"；要求局部成块 + 整体扩张（头部先成形 → 身体 → 细节收口）。
2. **自动加豆 → 用户主动拼入**：拼点自动进作品让用户觉得"系统自己拼的"；
   改为「用户控制动作、系统控制落点」：单击拼一颗、长按加速连拼。
3. **作品详情页砍掉训练分项**（前/后鼻音/对比/句子/听辨分钟、训练组数）与「继续练习」按钮；
   详情页只回答：这是什么作品 / 拼到多少 / 有多少待拼 / 怎么继续拼。
4. 数据模型随之拆分：`earnedBeads`（单一值，结算即入账）→ `placedBeads + pendingBeads`
   （用户选择 `pending_beads` 方案，弃用 `last_animated_progress` 重播方案）。
5. 作品墙未开始作品：**当天内试过「降饱和幽灵预览」（灰度+半透明可辨认）后被用户否决**——
   用户明确偏好「没有激活之前看不到内容，就是一个轮廓」；最终态 = 毛坯点阵轮廓
   （fill_order 全不点亮，CSS `.bead-art .bead:not(.on)` 灰点），ghost 方案当日移除。

## 2. 实现

### 区域成块 fill_order（`scripts/convert_webfem_csv.py` build_fill_order 重写）

- 同色 4 邻域连通块划分；面积 ≥ max(8, 总数×0.4%) 为主体块，其余为细节块。
- 主体块按（顶行升序，面积降序，左列升序，颜色）排序 → 自上而下、大块优先；
  块内从左上首格 **BFS 外扩**（局部从一个种子连续生长成片）。
- 细碎块（纹理/高光）统一排最后收口，同规则排序。
- **纯几何/颜色排序，无随机数**（原 Fisher–Yates seed 方案废弃）；同 grid 永远同序。
- 重新生成 `artwork_catalog_v2.json`（计数真值不变：4343/4232/3739/3871/4100/4119，合计 24404）。
- cat1 实测空间推进：0–15% 行 5–46（头部）；15–35% 行 18–73；35–65% 行 49–90；末段细节收口；
  同色相邻格顺序接近率（±30 位）100%（完全成块）。

### pending 拼入模型（`prototype_static/app.js`）

- 记录字段：`placedBeads`（已亲手拼入）/ `pendingBeads`（待拼）；loadProgress v2→v3 迁移：
  旧 `earnedBeads` 整体迁为 `placedBeads`（行为与迁移前视觉一致）。
- 结算：`beadBalance += total_beads` 一次 → `earmarkPending()` 把**整颗**预登记给当前作品
  （上限 = 剩余空间；未满 1 颗的浮点余量留口袋；作品完成后口袋余量等切换下一张再登记）。
- **结算不再直接点亮任何珠子、不再触发完成**；完成只发生在拼入侧。
- 拼入（详情弹层）：主按钮「按住拼入 · 剩 N 颗」——单击 1 颗；按住 320ms 后进入 rAF 连拼，
  速度 6 颗/秒 → 约 40 颗/秒（5 秒内加速）；`placedBeads++ / pendingBeads--` 严格 1:1；
  每批 playPlaceTick（WebAudio 三角波短音，限频 ~14 次/秒）+ navigator.vibrate(8)。
- 拼满最后一颗 → 详情弹层内「熨烫 / 融合」仪式（1.8s）→ 成品庆祝（系列第 6 件触发
  「猫猫系列 6/6 完成」一次）；原完成页庆祝函数 `renderArtworkCelebration` 删除
  （结算不再可能直接完成作品）。
- 详情页按钮按状态切换：待拼>0 → 按住拼入；未开始/非当前 → 开始拼这张 / 设为当前作品；
  当前但无待拼 → 弱化「去训练赚拼点」；完成 → 知道了。
- 结算页（字词/句子/辨音通用）改为「待拼 · 作品名 +N」轻提示卡 +「去拼入」主按钮。
- 作品墙卡片：未开始 = 毛坯点阵轮廓（0 颗点亮，看不到内容）；进行中 =
  placed 点亮 + 毛坯点 + 「待拼 +N」角标；完成 = 全彩 ✓。（幽灵预览方案当日弃用，见决策 5）

## 3. 过程中抓到并修掉的 bug

- **结算双倍入账**：改 applyReward 时在函数尾部重复了 `beadBalance += beads`（函数开头原有一处），
  每次结算余额翻倍 → 待拼双倍。表现为"待拼比挣的多 600"。已修（只保留开头一处入账），
  修复后实测 +600 结算 → 待拼恰好 +600；房间不足时按剩余空间截断（58 颗作品只收 58）。
- 修复前测试档案已产生幻影待拼（含 1200 颗双发残留 + 麦克风被拼成），走查数据非真实进度。
