## 0. 一句话现状

四个活动（**字词 / 句子 / 听辨 / 错题复习**）→ 统一结算入口 `/api/achievement/settle` →
产出「拼点」→ 拼点自动流进**正在拼的像素画作品**（拼豆画）→ 拼满一件 → 庆祝 →
收进作品墙 → 选下一张。单机本地原型：**权威进度在浏览器 localStorage**，服务端结算无状态
（只算钱 + 每日上限钳制），事件追加落盘 `events.jsonl` 供数值复盘。

## 1. 收入侧：四类活动的计价

### 1.1 计价总表（配置 `achievement_config_v1.json` v3）

| 活动 | 基础计价 | 完成奖励 | 单轮典型收益 | 每分钟单价 | 中途退出 |
|---|---|---|---|---|---|
| 字词 | 时长表：5/10/15/20 分钟 → 6/12/20/28 | 完整完成 +2 | 10 分钟 = **14** | ≈1.4 | ≥20% 按比例给基础分（四舍五入），无任何加成；<20% 不给 |
| 句子 | 每句 **0.5**（四舍五入取整） | 整轮完成 +1 | 10 句 = **6** | ≈1.0–1.5 | 已完成句数 ≥20% 按句数给基础分；<20% 不给 |
| 听辨 | **当日轮次递减**：第 1 轮 **2**、第 2/3 轮 **1**、第 4 轮起平均 **0.5/轮**（0/1 交替发放）；每轮 = 词库练习一批 50/100/150 词（默认 50，约 3–6 分钟） | 全对彩蛋 **+1**（仅当天第 1 轮完整完成） | 第 1 轮全对 = **3**、有错 = **2** | ≈0.3–0.7 | 正确音节占比 ≥20% 时按「该轮基础 × 正确率」向下取整，无加成、**不占轮次**；<20% 不给 |
| 错题复习 | 完成全部「今日待复习」一次性 **+2** | — | = **2** | — | 无退出结算概念（答完为止） |

### 1.2 各活动的规则细节

**字词**（语料 16,156 词，Profile 生成，5/10/15/20 分钟自选）
- 完整完成 = 自动听读循环走到时间结束。`base + 完成2 + streak + 三练` 四块可叠加。
- 中途退出（跳过/退出）：按实际时间比例 × 基础分，四舍五入；低于 20% 时间拿 0。
- 每个训练入口的「练多久」提示行会明示对应拼点（如「10 分钟 · +12 拼点」，不含完成/加成）。

**句子**（582 条前后鼻密集句示范切片，10 句/轮，约 4–6 分钟）
- 每句 0.5 → 10 句 = 5 + 整轮完成 1 = **6**。开口跟读的"开口补偿"。
- 中途退出 ≥20% 按已完成句数给（如 10 句中做 3 句 = round(1.5)=2）。
- 入口选择界面明示「N 句 · +X 拼点」（与服务端口径一致，前端复刻了 Python round 的银行家舍入）。

**听辨**（3,796 词 4,158 判断点，**每轮 = 词库练习一批 50/100/150 词**（默认 50，约 3–6 分钟/轮），
无音频纯点按钮；辨音 Tab「词库练习」卡，与「错题复习」构成双卡片，详见 `handoff/modules/discrimination.md`）
- **轮次递减防刷**（2026-08-16 设计师共识版落地：否决"轮次越来越长"、保留"每轮 10 词"；
  **v3 起轮长改为可选的 50/100/150 词/轮**，一轮变长本身已大幅压低每分钟收益）：
  - 第 1 轮 2、第 2 轮 1、第 3 轮 1、第 4 轮起 0.5/轮；
  - 拼点必须整数 → 用「累计值向下取整后求差」发放：第 4 轮 0、第 5 轮 1、第 6 轮 0、第 7 轮 1…长期平均恰好 0.5。
- 全对彩蛋 +1 **仅当天第 1 轮**；第 2 轮起全对只显示 ✦ 视觉标记，无拼点。
- 连错（≥2 整词连错）只扣**答题得分**（警报条 + 每词 -1 分），**不扣拼点**——只奖不罚。
- 退出轮：按「该轮基础 × 正确率」向下取整（≥20% 门槛），**不占当日轮次**（轮次只数完整完成的轮）。

**错题复习**（听辨 v3，2026-08-23）
- 主词库答错的词进复习系统：每词 1 天 → 3 天 → 7 天 → 掌握退出；错过日期滚动累积不清零。
- 当天完成全部「今日待复习」→ 一次性 +2（`review_reward`，**占位值**）。
- 与 streak / 三练**解耦**：不发 streak、不入三练、不占听辨轮次；当日防重由客户端 localStorage（`pth-review-award-v1`）记录。

### 1.3 反馈与明示

- 结算页统一「拼豆掉落」动画（reward-burst，豆子数 = min(拼点, 6)）+「正在拼」像素点亮动画（before% → after%）；
- 特殊提示行：🔥 streak 加成、✨ 今日三练达成、⚠ 单日上限、完成不足 20% 无拼点、「今日听辨拼点已领完（前 3 轮）」；
- 今日三练进度行（字词 ✓/○ · 句子 ✓/○ · 听辨 ✓/○ + 再完成 N 项 +2）；
- 历史页分类型行（字词青/句子绿/听辨紫/复习橙，含 ✦全对、🔥 streak、三练 +2 徽章，0 拼点显示「—」）。

## 2. 三层叠加规则（第 2、3 层）

### 2.1 今日三练组合奖励（第 2 层）

- 条件：**当天**字词 + 句子 + 听辨**各完整完成 ≥1 次**（复习不算）。
- 奖励：**+2**（`combo_bonus`），每天只发一次，在第三项完成的那轮结算里**即时发放**；
  之后再练显示「今日三练已完成 · +2 拼点已入账」。
- 判定：客户端在结算请求里上报三类的 `*_completed_today` 与 `combo_awarded_today`，服务端只按上报值计算（单机原型口径）。
- 前端记录 `comboAwardedDayKey`（localStorage）防重发。

### 2.2 连续训练 streak（第 3 层）

- 概念：**连续自然日**有训练记录就算连续。任一类**完整完成**一轮即算当天打卡（产品口径）。
- 加成：当天**首个**完整完成的结算里发 `min(5, N−1)` 拼点——第 2 天 +1、第 3 天 +2 … 第 6 天起 +5 封顶；每天只发一次；错过一天清零重来。
- 天数推导：前端按本地日期从 `sessions[].dayKey` 回溯连续自然日（今天练了 → 从今天回数；今天没练但昨天练了 → 显示到昨天为止）。

### 2.3 每日上限（保险丝）

- `daily_bead_cap = 100`/天：服务端按客户端上报的 `beads_earned_today` 钳制本次下发总量（`capped` 标记），超出显示「今日拼点已达上限」。
- 它是**软约束**（客户端可谎报），定位是"异常保险丝"而非反作弊边界；单机无账号无服务端反作弊。
- 正常日远够不到 100（标准日 ≈ 24–25）。

### 2.4 标准日经济（节奏基准）

| 组合 | 拼点 |
|---|---|
| 字词 10 分（14）+ 句子一轮（6）+ 听辨第 1 轮（2 或全对 3）| **22–23** |
| 加 今日三练 +2 | **24–25** |
| 对应作品节奏 | 小件（56–58）≈ **2 天半**；中件（90–104）≈ 4 天；大件（116）≈ 5 天 |

## 3. 支出侧：作品系统（拼豆画）

### 3.1 作品目录（`artwork_catalog_v1.json`，6 件）

| 作品 | 分类 | 层级 | 拼豆数 | 解锁规则 | 一句话 |
|---|---|---|---|---|---|
| 麦克风 | 声音 | 小 | 58 | 新手三选一（starter） | 第一支麦，开口就有声 |
| 耳机 | 声音 | 小 | 56 | 新手三选一（starter） | 把标准音听进耳朵里 |
| 声波小怪 | 角色 | 小 | 58 | 新手三选一（starter） | 它收集每一次跟读的声波 |
| 小录音机 | 声音 | 中 | 104 | 完成 1 件后解锁 | 把练习一格格录下来 |
| 霓虹招牌 | 潮流 | 中 | 90 | 完成 1 件后解锁 | 练到字正腔圆，灯就亮了 |
| 前后鼻音双子 | 角色 | 中* | 116 | 完成 1 件后解锁 | n 和 ng，本来就是一对 |

\* 在目录里标 `medium`，但 README/设计简报以「小 56/56/58 · 中 90/104 · **大 116**」叙事——
层级命名与叙事不一致（见 §5）。

每件作品 = 像素网格（canvas 14×11 ~ 22×12）+ 调色板 + `active_bead_count`（程序校验与网格实际非空格数一致），
填充顺序统一 `row-major`（行优先），点亮动画 70ms/颗。

### 3.2 完整流程（用户视角）

1. **新手三选一**：首次进入必须从 麦克风 / 耳机 / 声波小怪 中选一张（`onboardingDone`），之后才能开始训练。
2. **日常**：训练所得拼点 → 先入「拼点口袋」`beadBalance` → **立即全部倒入当前作品** `earnedBeads`
   （只填当前作品；作品装不下的余量留在口袋里，等选下一张时再倒）。
3. **拼满**：`earnedBeads ≥ active_bead_count` → 打 `completedAt` + 第 N 件编号 → 庆祝页
   （✦ 完成了！+ 动画 + 「这是你的第 N 件拼豆作品 · 由 X 分钟真实训练拼成」）→「收进作品墙」或「选择下一张」。
4. **选下一张**：picker 列出「已解锁且未完成、非当前」的作品；**完成任意 1 件后解锁其余 3 件**（after_completions=1）。
5. **作品墙**（右上角「作品」）：四区展示——**正在拼**（有独立分区）/ **可选** / **已完成**（✓ + 「N 分钟拼成」）/ **未解锁**（🔒 剪影 + 「完成 1 件作品后解锁」）。点任意卡片开**详情弹层**。
6. **作品详情**：大图 + 分类 + 标语 + 状态行（正在拼 X/N · P% / 已拼 / 还没开始）+ 进度条 +
   分项统计（**前鼻音 / 后鼻音 / 对比 / 句子练习 / 听辨练习** 分钟 + 训练组数）+ 完成元信息
   （「这张作品由 N 分钟真实训练拼成」）+ 动作按钮（继续练习 / 开始拼这张 / 知道了）。
7. **作品本身无完成奖励**：拼满即庆祝，「完成」本身不再返拼点（解锁即额外收益）。

### 3.3 数据口径

- 每件作品的记录：`earnedBeads / totalMinutes / sessionCount / frontNasalMinutes / backNasalMinutes / contrastMinutes / sentenceMinutes / discrimMinutes / startedAt / completedAt / completedNumber`。
- 分项分钟按**训练入口**记账（字词入口 → 前鼻/后鼻/对比；句子/听辨 → 对应分钟），与生成器 Profile 无关。
- **拼点余额在 UI 任何地方都不展示**——只有历史页有「累计拼点」（= 所有 session 的 beads 之和，非口袋余额）。

## 4. 数据与可信度

| 数据 | 位置 | 说明 |
|---|---|---|
| 用户进度 | 浏览器 localStorage `pth-nasal-progress-v1` | **权威**：拼点/作品/会话/三练标记/音筛选。结构字段：`beadBalance / currentArtworkId / artworks{} / sessions[]（≤300 条，超了裁掉最旧的）/ comboAwardedDayKey / entryFilters / onboardingDone` |
| 复习奖励防重 | localStorage `pth-review-award-v1` | 「今日复习 +2 已发」当天标记 |
| 服务端结算 | `/api/achievement/settle` | **无状态**：纯计算（费率 + 上限钳制），客户端上报 streak/轮次/当日已得拼点 |
| 服务端只读 | `GET /api/achievement` | 下发 `achievement_config` + `artworks`（含 fill_order） |
| 听辨状态 | `data/derived/prototype/discrim_progress.json` | 服务端：词库游标、错词排期（stage/nextReviewAt）、单词统计；**用户真实数据勿清空** |
| 审计日志 | `data/derived/prototype/logs/events.jsonl` | 四类事件，含 `beads_awarded / combo_bonus / round_today / streak_*` 字段，供数值复盘 |

**防作弊程度**：单机原型，无账号、无服务端反作弊。任何约束（上限、防重、轮次）都建立在客户端自报 + localStorage 上；清 localStorage 即重置进度。

## 5. 已知不一致 / 观察点（评审前先知道，评审时可一并裁决）

1. **streak 打卡口径与文档不符**：文档/文案说「三类任一轮**完整完成**才算打卡」，
   但 `computeStreak()` 把**所有** session（含中途退出、含复习）的 dayKey 都计入连续天数。
   加成发放才是「当天首个完整完成」。→ 需要决策：显示口径改不改（只算完整完成？只算三类？复习算不算？退出轮算不算？）。
2. **听辨退出轮的费率漏洞**：退出轮「不占轮次」+「按第 1 轮费率 × 正确率」→ 理论上可
   每轮差一点就退出，永远按第 1 轮 2 分计价（完整完成反而进入第 2 轮 1 分）。
   单机原型是软约束，但要意识到这个洞存在。类似的：退出轮不打「今日三练」的完整完成标记，不会误触发三练。
3. **README 旧费率残留**：README「本地练习原型」一节仍写着旧 v1 费率
   （句子每句 0.4、听辨每正确音节 0.2 + 全对 +2），与当前 v3（句子 0.5、轮次递减、彩蛋 +1）不一致；
   同文件「统一奖励系统」一节是新的。评审材料以本文档为准，README 需顺手修正。
4. **作品层级命名**：`nasal_twins`（116 颗）目录里是 `medium`，没有真正意义上的 `large` tier；
   小/中/大的叙事与数据不一致（也许该引入「大」档，或接受 3 档中最大即 116）。
5. **`review_reward=2` 是占位值**，等定稿。
6. **拼点口袋不可见**：完成一件后、选下一张前，「口袋」里多出来的拼点没有展示位置；
   首页顶栏只有 今日/累计分钟 + 连续天数（无拼点余额）。
7. **sessions 300 条截断**：streak 天数、累计分钟、累计拼点都由 sessions 推导，超过 300 条后
   （每天 3–4 条约 2–3 个月）早期记录被裁剪，**累计值会悄悄变小**（口径是"最近 300 条"而非"全部"）。
8. **无长期收藏结构**：全部 6 件拼完即「毕业」，没有图鉴/系列/层级/榜单/自定义作品等长期目标
   （设计简报 §四.4 也提过；简报名为「长期方向本轮不做」，现在可能是时候做了）。
9. **复习与三练/打卡的关系**（待定）：复习 +2 与三练 +2、streak 加成互不关联；若产品想
   「复习也算三练一项」或「复习不参与 streak 打卡」，是口径决策。
10. **分数 vs 拼点分离**：听辨「答题得分」（连错扣分）与「拼点」是两条线——得分影响本轮
   展示与事件日志，拼点只受轮次/全对/上限影响。评审时如想「扣分也扣拼点」需明确（历史上明确只奖不罚）。
