## 目标与首轮交付

建立一套统一、舒适、能反复听的交互声音。适合青少年与成年人：可爱、温暖、细腻、有轻微弹性和实物触感。配合奶油背景、青／橙／紫角色、圆润卡片与拼豆作品；训练中保持安静，奖励和完成时更丰富。

**首轮要有实际可试听的成果，不能只交一段文字方案。** 先完成声音事件清单和原创样音，并制作独立的本地试听页面，在新任务的右侧面板打开。页面要能单独试听，也能模拟一小段答题、长按拼豆和完成仪式，方便用户判断连续听是否舒服。

可为“点击、答对、拼豆、完成”制作两组小范围风格对比，并明确推荐其中一组；随后以推荐方向扩展完整样音。技术细节由执行者判断，不要求用户先选工具或学习音频术语。首轮以试听方案和素材为交付重点，正式 APP 的接入位置、配置与验证列清楚，后续在新对话中继续调整和接入。

## 声音方向

- 建议主方向：柔软木质敲击、圆润的珠子轻碰、短促的弹性气泡，少量温和亮音作点缀；声音起落平滑，尾音干净。
- 答对清楚但克制，答错用低强度的提醒；连续答错不升级成惩罚性警报。
- 同一套声音共享音色与简短动机；完成奖励可以更饱满，但不要每次点击都播放旋律。
- 练习过程不铺背景音乐，不加入角色口播，不覆盖示范音。前鼻／后鼻是两种学习选项，不能分别绑定“正确／错误”的声音暗示。
- 下表时长是起点，最终以实际连续试听为准，避免高频刺耳、突然爆响和拖长节奏。

## 场景清单

| 场景 | 设计意图与触发建议 | 建议时长 |
|---|---|---|
| 按钮确认、选项切换 | 轻微触感；只在值得确认的操作出现，普通导航可保持安静 | 40–100 ms |
| 开始训练 | 简短、温和的起步提示，结束后再进入示范音 | 150–350 ms |
| 示范结束、进入跟读 | 可选的轻提示；不得遮住读音尾部，也不要每秒滴答 | 60–150 ms |
| 辨音答对 | 清晰的小肯定，连续答题不会烦 | 120–250 ms |
| 辨音答错 | 柔和、容易分辨的纠错提示；保留文字反馈 | 120–250 ms |
| 趁热巩固、跨天复习 | 评估是否复用开始／答题音，避免每个状态都新增声响 | 复用为主 |
| 训练结算、奖励到账 | 有获得感的短音，多个奖励同时出现时合并播放 | 350–800 ms |
| 今日三练完成 | 在结算音基础上小幅增强，只在实际达成时播放 | 600–1000 ms |
| 单颗拼入 | 珠子落位、圆润轻碰；准备少量自然变化 | 30–90 ms |
| 按住连续拼入 | 随拼入节奏变化、限制密度，松手立即停止，不积压音符 | 持续时序 |
| 熨烫、融合 | 轻柔的融合质感，贴合现有约 1.8 秒仪式，不刺耳 | 按动画控制 |
| 单件作品完成／系列集齐 | 同一家族的两级庆祝，系列完成可以稍丰富 | 0.8–1.8 s |
| 暂停、退出、加载失败 | 逐项判断是否需要声音；提示不依赖声音，失败可只用文字 | 安静优先 |

允许合理合并或减少音效。交付清单必须说明每个场景是“独立音效、复用音效、保持安静”中的哪种，并给出一句原因。

## 现有实现与接入边界

目前已有示范音、标准音视频，以及 `src/pth_corpus/prototype_static/app.js` 中的 `ensureAudio()` 和 `playPlaceTick(count)`：拼豆用 Web Audio 三角波发出约 60 ms 的简单提示，带有限流与震动。最终接入时替换或收编此逻辑，避免新旧声音叠加。

- 字词、句子跟读目前是**计时**，没有判断用户是否读对；计时结束不能播放“发音正确”音。辨音有真实正误判断，可播放答对／答错反馈。
- 声音播放优先级：示范语音／视频 > 必要反馈 > 装饰声音。设计清楚打断、丢弃或延后策略，不能靠降低示范音音量给装饰音让路。
- 连续拼豆会加速，不能每一颗都创建完整长音。采用限流、少量变体、并发上限，避免声音堆积；以现有实际拼入事件驱动。
- 准备统一声音管理模块与事件命名，集中管理音量、静音、去重、限流、播放结束与销毁；首轮试听页也使用可复用的实现。
- 遵守浏览器用户手势解锁 AudioContext 的要求，兼顾挂起恢复、切后台与页面退出；恢复时不补播积压反馈。
- 音效开关和音量独立于教学音频。偏好用单独存储键，不修改训练进度结构；支持键盘操作。关闭音效后所有文字与图形反馈仍完整。
- 不改训练时长、复习间隔、奖励档位、拼豆规则、作品网格和填充顺序，不移动示范音文件。

即使最终采用实时 Web Audio，也应保留可导出的样音和可复现参数，便于后续换工具、比较和交接。
